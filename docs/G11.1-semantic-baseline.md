## Minimal Claim C1

> **For every evolution request admitted by the design-level contract, the implementation preserves the contract's explicitly stated safety and atomicity properties; for requests made stale by intervening evolution, the implementation applies the contract's temporal-tolerance rule.**

The Claim is intentionally limited to properties that the recovered design-level material explicitly states:

- **Capability safety:** authorization/capability requirements are respected.
- **Structural atomicity:** structurally invalid evolution plans do not partially mutate evolution state.
- **Build-then-commit atomicity:** a failed build does not partially commit the resulting evolution.
- **Temporal tolerance:** a request that has become stale is handled according to the contract's tolerance rule rather than invalidating unrelated valid requests.

The Claim does **not** assert any additional exact state-transition semantics that are not explicitly specified by the design-level source.

## Independent Oracle O1

O1 is a finite set of falsifiable contract predicates over observable pre/post state and outcome. Each predicate is evaluated from the design-level rule before the implementation result is inspected.

### O1-A — Capability safety

For an evolution request requiring a capability, the observable result must satisfy the design-level authorization rule: an unauthorized or ineligible request is not admitted as an authorized evolution operation. A case in which an ineligible entity is treated as an authorized evolution target is an Oracle failure.

### O1-B — Structural atomicity

For a structurally invalid plan, compare observable evolution state immediately before and after application. The required result is **zero evolution-state mutation**. Any observable partial death, birth, genealogy, generation, or equivalent evolution-state mutation makes O1 fail.

### O1-C — Build-then-commit atomicity

For an otherwise admissible plan whose child construction/build fails, compare observable evolution state immediately before and after application. The required result is **no committed evolution mutation**. In particular, the recovered design-level material explicitly requires no deaths, no children, no generation bump, and no LifeGraph mutation; the failure itself may be recorded as the contract permits. Any committed evolution mutation makes O1 fail.

### O1-D — Temporal tolerance

For a request that was valid when planned but becomes stale because the referenced entity disappears before application, the observable result must be **individual tolerance**: the stale request is skipped/ignored according to the contract, and unrelated valid requests in the same application are not invalidated solely by that stale request. Treating the stale request as a plan-wide error, or thereby invalidating an unrelated valid request, makes O1 fail.

### Scope boundary for successful valid requests

O1 does **not** impose an additional exact success-state oracle beyond the four properties above. Exact genealogy, generation, queue, fossil, and audit transitions remain outside this Gate unless separately specified by the frozen design-level contract. This is a deliberate scope limitation, not an assertion that arbitrary successful behavior is semantically correct.

The four predicates above are the complete current G11.1 oracle. No additional success semantics may be inferred from the implementation during G11 test design.

## Independence test

Before G11.1 is frozen, the following must be demonstrated:

- C1 can be stated without naming implementation symbols.
- Every included property has an identifiable source in the recovered design material and the canonical v1.0 file.
- O1 can be evaluated without executing production implementation code.
- Expected outcomes can be determined before observing the implementation result.
- Each included predicate has a finite observable failure condition.
- No G11 test is used as a source for defining C1 or O1.
- No implementation detail is promoted to semantic law merely because the current tests assert it.
- The canonical v1.0 source is frozen by exact commit SHA before G11.1 is frozen.

## Explicit non-claims

This Gate does **not** currently establish:

- a complete abstract state-transition relation;
- exact generation semantics;
- exact genealogy semantics;
- exact runnable-queue semantics;
- exact fossil/death metadata semantics;
- exact audit-state semantics.

Those properties require additional independent normative specification before they can become G11 claims.
